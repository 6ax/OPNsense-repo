# Pinned upstream source archives

`upstream_source.py` is the archive validation primitive for plugins maintained
in another repository. It does not register a plugin, stage installed files,
execute downloaded code, download assets, or authorize signing or publication.
Existing local-source staging records continue to use their original verification paths.

A reviewed JSON lock contains exactly seven string fields:

| Field | Required value |
| --- | --- |
| `repository` | GitHub owner/repository |
| `tag` | Versioned release tag, such as `v1.2.3` |
| `commit` | Full lowercase 40-character source revision |
| `url` | HTTPS `github.com/OWNER/REPO/releases/download/TAG/ASSET.tar.gz` |
| `sha256` | Lowercase SHA256 of the compressed archive |
| `root` | Single root directory in that archive |
| `plugin` | Relative plugin subtree under the archive root |

The lock author must independently review the release tag's source revision and
asset provenance. An archive digest binds its bytes; it does not independently
prove the publisher's tag/commit assertion. Do not create a release lock from a
mutable branch, an unreviewed asset, or an unsigned development package.

With a locally cached archive and a reviewed lock:

```sh
python3 packaging/upstream_source.py --archive /path/to/source.tar.gz --lock /path/to/source.json
```

The command verifies the compressed digest before parsing, bounds compressed
bytes, decompression, member count and expanded file bytes, and reports the
complete source file inventory and per-file SHA256. It rejects duplicate paths,
noncanonical paths, root escapes, links, sparse files, devices, privileged modes,
file/directory collisions and a missing plugin subtree. It never extracts files
onto the host. A private temporary spool bounds decompression before tar headers
are parsed and is closed on both success and failure.

`nethub_source.py` provides the NetHub-specific copied-file reconstruction. It
reads the verified inventory, reproduces the builder's source-copy exclusions,
returns all four exact lifecycle hooks, checks the package/product version and
identity, and fingerprints ten compiler, module, builder and license-collector
inputs. It refuses copied files outside `/usr/local` or in the generated binary
directory. It does not execute upstream scripts or compile a client.

## Comparing a candidate package

`nethub_package.py` compares a candidate with the reconstructed source and a
separately reviewed build record. It reuses the publication verifier's existing
file-inventory and lifecycle-hook comparisons. Extracting those comparisons into
shared functions does not change the checks for existing registered plugins.

The build record is a JSON object with exactly these fields:

| Field | Required value |
| --- | --- |
| `schema_version` | Integer `1` |
| `source_commit`, `source_archive_sha256` | Exact source-lock values |
| `abi` | Reviewed native `FreeBSD:MAJOR:amd64` target |
| `compiler`, `frp_version` | Source compiler/frp pins |
| `build_input_sha256` | All ten fingerprints returned by the source adapter |
| `generated_files` | Complete relative generated-file paths mapped to SHA256 |

The generated-file directory contains the independent reviewed build outputs,
relative to `/usr/local/opnsense/nethub-agent/bin/`. It must include `frpc`,
`FRP_BUILD.json`, `FRP_VERSION`, `FRP_LICENSE` and the complete `frpc-licenses/`
tree. The Go license and the versioned upstream frp license are mandatory.
The collector's canonical `frpc-licenses/modules.txt` must cover exactly the
module license directories, each containing a collected license or notice.
The record itself also requires a separately reviewed SHA256 supplied explicitly
to the command. Create and review these pins from an independent accepted build;
**deriving the record or cache from the candidate under test is not acceptance**.

```sh
python3 packaging/nethub_package.py \
  --package /path/to/candidate.pkg \
  --archive /path/to/source.tar.gz \
  --source-lock /path/to/source.json \
  --build-record /path/to/reviewed-build.json \
  --build-record-sha256 "$REVIEWED_BUILD_RECORD_SHA256" \
  --generated-directory /path/to/independent-generated-files
```

The command binds the generated bytes to their complete inventory, source inputs,
compiler, module locks and frpc profile. It checks the FreeBSD ELF target, receipt,
version and corresponding license bytes without executing the binary. It then
compares candidate metadata, ABI, dependencies, flat size, file ownership/modes,
complete copied/generated contents and all four hooks. The package and catalog
manifests must agree, and unreviewed manifest fields or per-file attributes are
rejected. Both archive readers used by the existing verifier remain required.
All candidate readers and the reported package digest use one bounded private
snapshot. The reported digest identifies those verified bytes, not a mutable
filename; the release process must match the actual package's digest before
signing or publishing it.

Success proves candidate-byte agreement with the supplied reviewed inputs. It
does not independently prove the reviewer's build provenance, native behavior,
the completeness of the reviewer's dependency-license collection, or release
approval. The command explicitly reports native lifecycle/release acceptance as
false.

The formal repository registers `os-nethub-agent` 0.0.19 for FreeBSD 15 amd64.
Its staging record pins the exact package tested in an isolated OPNsense VM,
the upstream Beta source archive, and the reviewed independent build record.
For repository verification, generated files are read from the private package
snapshot and compared to the independent record's committed digests. The
record and its digests must come from a separate build. The verifier downloads
the pinned source archive or reads it from `NETHUB_SOURCE_ARCHIVE` if an
operator has cached it locally. Both paths check the same archive digest.

Validation: `python3 -B -m unittest discover -s tests -p test_upstream_source.py -v`.
The adapter and candidate tests use `test_nethub_source.py` and
`test_nethub_package.py` with the same command. The existing shared-suite discovery
includes all three suites. Synthetic source archives, ELF headers and packages
in these tests are fixtures, not release records or native build acceptance.
